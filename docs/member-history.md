# 회원 기록·기존 학생 연결 운영 절차

## 현재 범위와 안전 경계

- 최신 main `f6ea9c16039fc034c91653d37611ea9188e78cb0` 기준.
- 추가 Classroom OAuth/API/People API를 사용하지 않는다. 운영 로그인 scope/PKCE/state/nonce/쿠키/Origin/CSRF는 유지한다.
- 현재 검토 큐의 출처인 D1 `articles`, `assignment_recipients`, `article_edits`의 소유 Google ID만 조사한다. 이름/학번/이메일 번호로 소유권을 추정하거나 병합하지 않는다.
- 2026-10-25 읽기 전용 조사: 고유 기존 학생 ID 20명, 기존 Google ID 연결 회원 2명, 사전 등록 대기 18명, Google ID 형식 검토 대상 0명. 현재 D1의 Classroom `article_edits`에는 1명/1건이 있고 이미 회원과 연결됨. **전체 Google Classroom 외부 제출자 수를 의미하지 않는다.**
- 민감한 대상 명단과 승인용 SQL은 공개 repo/PR에 넣지 않는다. 이번 작업에서 운영 회원 등록/삭제/코드 변경/배포는 하지 않는다.

## 사전 등록과 최초 로그인

이메일이 없는 과거 학생에게 임의의 학교 이메일이나 Google ID를 만들 수 없다. 기존 회원 테이블의 필수 이메일/기수 제약을 완화하는 대신 `member_legacy_students`라는 작은 일회성 연결 대기 명단을 둔다. 별도 로그인이나 회원 관리 시스템이 아니다.

1. `scripts/legacy-members.mjs`의 `existingStudentSql`로 현재 D1 소유 ID와 가장 최근 저장된 과제 수신자 표시 이름만 읽는다.
2. `planLegacyMembers(source,members)`는 실제 Google ID 형태(10~30자리 숫자)만 허용하고, `members.google_sub`가 일치하는 회원은 제외한다. 알 수 없는 식별자는 검토 대상으로 남긴다. 표시 이름의 5자리 학번만 파싱하고, 모르는 이메일/기수/학번은 생성하지 않는다.
3. `scripts/plan-existing-members.mjs <private-source.json> <private-members.json> <private-output.json>`은 공개 repo 밖에 승인용 계획과 SQL만 생성한다. DB 접속/적용 기능이 없다. 동일 ID 재실행은 `ON CONFLICT DO NOTHING`으로 멱등이다.
4. **운영 승인 후** 대기 명단을 적재하면 회원 관리의 전체 회원 목록에 이메일·기수 확인 대기 상태로 표시된다. 기존 업무 소유 ID는 변경하지 않는다. 확인 전 신규 과제 수신자로 자동 확대하지 않는다.
5. 최초 OAuth에서 검증된 `sub`와 학교 이메일로 기존 회원을 먼저 조회한다. 기존 비활성/이메일 충돌은 가입 코드로 우회할 수 없다.
6. 기존 회원이 없고 검증된 `sub`가 대기 명단과 정확히 일치할 때만, 검증된 학교 이메일과 입학 연도로 실제 회원을 원자적으로 생성/연결한다. 기수·학번 충돌은 관리자 확인으로 중단한다. 이메일로 이미 등록된 회원은 기존 ID를 그대로 연결한다.
7. 이 경로와 일치하지 않는 신규 학생만 기존 공통 가입 코드 흐름을 사용한다. 이름이 같은 다른 Google 계정은 대기 기록을 가져갈 수 없다.

## 가입 코드 표시

- 기존 PBKDF2-SHA256/100,000회 hash/salt 검증과 rate limit을 유지한다.
- 새 코드 저장 시 기존 `SESSION_SECRET`으로 AES-GCM 암호화한 별도 표시용 값을 함께 저장한다. 관리자 GET/PUT 응답에만 평문을 돌려주고 `no-store`를 유지한다. 로그/소스/학생 응답에는 포함하지 않는다.
- 예전 해시만 있는 코드는 복원할 수 없다. 기존 코드의 검증은 그대로 유지하면서 1회 변경 안내만 표시한다. 임의 초기화/코드 생성은 하지 않는다.
- 최소 길이 12~128자 정책을 유지한다. 예시의 짧은 숫자 코드를 위해 보안을 완화하지 않는다.
- 회원 관리 → 학생 공통 가입 코드 설정 → 코드 변경하기 → 저장. 코드 재설정/활성화는 운영 관리자가 결정한다.

## 정보 동기화와 활동 종료

- 인증된 Google 표시 이름이 `5자리 학번 + 이름` 패턴에 맞을 때 이름·현재 학번을 동기화한다. 회원 ID/sub/이메일/기수/소유권/기존 데이터는 유지한다.
- 형식 오류/제어문자/중복 학번은 기존 프로필을 유지한다. 소유권을 이름으로 연결하지 않는다.
- 마지막 로그인 시각을 기록한다. 보존 audit을 남기며 변경 시 기존 auth_version 세션 보호를 유지한다.
- 현재 학번이 3xxxx이거나 KST 3월1일 기준 활동 기수를 벗어나면 신규 배부 대상에서 제외한다. active 값을 바꾸거나 기존 과제/통계를 삭제하지 않는다. 전체 회원 조회에서는 계속 확인한다.

## 상세 기록과 삭제

- 관리자 전용 상세 GET: 기존 Google ID로만 기사/학생 제출 revision/과제 슬롯/로그인 전 배정/사진/편집 버전/저장된 Classroom 첨삭 메타데이터를 조회한다. 원고·내부 메모·Drive 토큰을 불필요하게 내려주지 않는다.
- 각 종류 50개씩 날짜/ID 정렬로 페이징한다. 과제 목록은 슬롯 기준, 기사 수는 고유 native article 기준이다. Classroom 저장 기록은 별도 표기하며 이름/제목이 같다는 이유로 서로 다른 문서를 합치지 않는다.
- native schema에는 실제 발행 완료 상태가 없어 `scheduled`를 **발행 예정**으로 명시한다. 외부 Classroom 전체 원본/실제 발행 여부는 추정하지 않는다.
- 현재·과거 기록의 ID는 기존 상세 화면으로 이동한다. 외부 Classroom에만 있는 원고를 새로 동기화하지 않는다.
- 삭제는 교사/본인 금지. 실제 업무 참조, meaningful audit, 미해결 과거 계정, 알 수 없는 신규 참조 schema, 조회 실패가 있으면 차단한다. 대기 명단이 남아 있는 동안 불확실한 무기록 계정 삭제도 보수적으로 차단한다.
- 등록 자체의 audit은 보존하되, 등록 audit만 있는 무기록 테스트 학생은 삭제 가능하다. 별도 요청/차단/성공 감사 기록과 삭제 tombstone을 남긴다. 관련 업무/CASCADE 삭제는 하지 않는다.
- DELETE는 이름/이메일/ID를 보여 주고 ‘영구 삭제’ 확인을 받는다. 서버에서 ID/이메일/auth_version/관리자/CSRF를 검증하고, D1 BEFORE DELETE trigger가 모든 기존 업무 참조를 다시 검사해 조회-삭제 사이 경쟁을 차단한다.

## 보고된 동명이인/중복 표시

운영 읽기 전용 조사에서 보고된 수동 회원은 1개, 과거 과제 식별자는 1개였지만 두 식별자는 연결돼 있지 않았다. 검토 큐는 기존 과제/기사 소유 ID와 로그인 전 회원을 각각 표시하므로 두 행이 생길 수 있다. 동일 기사 중복 생성으로 단정하거나 이름으로 합치지 않는다. 로그인 전 수동 회원은 실제 기사 소유자 카드와 별도의 ‘Google 계정 연결 대기 회원’ 목록에 보존하며, 검증된 Google 로그인 후 기존 회원 ID에 연결되면 Google ID 단위로 한 학생이 된다.

## Migration 0012와 적용 순서 — 별도 승인 필수

1. main/대상 DB/ledger/Time Travel bookmark를 재확인하고 암호화 백업의 격리 복원 검증을 먼저 수행한다.
2. **0012에는 기존 member_audit FK를 보존형 audit으로 옮기는 schema 전환이 있다.** 기존 행을 전부 복사한 뒤 표를 교체하며, 회원 삭제 후에도 감사 행이 남게 한다. 기존 업무 테이블과 회원 레코드는 삭제/초기화하지 않는다. 자동 migration 승인 목록에 넣지 않는다.
3. 승인 후 0012만 적용하고 기존 데이터 건수/내용, audit ID/내용, FK 무결성, bootstrap editor 보호, 코드 hash/활성 설정 보존을 확인한다.
4. 최신 D1 읽기 결과로 계획을 다시 생성하고 인원·식별 충돌을 확인한다. **별도 승인 후** 연결 대기 SQL만 원자적으로 적용한다. 기존 회원 일괄 생성/계정 병합/소유권 재작성은 없다.
5. Worker → 동일 commit Vercel 순서. 기존 교사/학생 코드 없는 로그인 및 연결, 코드 미설정/해시-only 상태를 확인한다. 운영 회원 삭제 테스트는 하지 않는다.
6. schema/인증 오류 시 중단한다. 임의 SQL 재실행/소유권 변경/Classroom 인증 복귀를 하지 않는다.

추가 R2/유료 리소스/예약 작업/Google 권한/초기 코드 생성은 필요 없다. 운영 사전 등록과 migration 및 배포는 이번 개발 PR의 승인 범위에 포함하지 않는다.
