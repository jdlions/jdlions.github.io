# 편집국 통합 대시보드

기준 main: `977ccdd37441bc67e2543a12fea7e6ce6c07a61a` (사진 관리 PR #65 병합 완료). 새로운 테이블·migration·index·외부 서비스는 추가하지 않는다. 기존 `/api/admin/dashboard`와 해시 라우터를 확장한다. 운영 데이터 조회/변경/배포는 하지 않는다.

## 집계 정의
- 전체 기사: `articles`의 저장된 기사 수. 검토 대기: `submitted` 상태(검토 중은 별도 상태).
- 미제출 과제: 진행 중인 캠페인에 배부된 기사 슬롯 수에서 제출 이상 상태(`submitted/reviewing/hold/approved/scheduled`)를 뺀 수. 수정 요청은 재제출 대기이므로 미제출에 포함한다. 로그인 전 회원 대상은 기존 `member:` 식별자와 슬롯 개수로 계산하며, 이미 존재하는 슬롯과 중복 계산하지 않는다. 회원·Google ID·과제 소유권은 변경하지 않는다.
- 사진: `is_deleted=0`인 실제 파일 레코드 수. 동일 기사에 사진 2개를 제출했다면 2장이다. 기사 미연결 학교/피처 사진도 포함한다. 유형이 다른 사진은 전체 수에만 포함된다. 학교·피처 목표는 각각 20장, 목표를 넘는 실제 수량도 그대로 표시한다.
- 제출 진행률은 전체 진행 과제 기준이다. 최근 시작 과제의 이름과 유형별 수치를 함께 표시한다. 마감은 슬롯 마감을 우선하고 캠페인 마감으로 보완한다. 미제출 슬롯 중 초과/72시간 이내 항목 최대 8개를 표시한다.
- 편집 파일은 가장 최근 연도·시즌 프로젝트의 `latest_version`에 연결된 완료 버전이다. 파일명·수정자 snapshot·업로드 시각·현재 활성 lock 담당자를 읽는다. 업로드 중 파일, 취소 버전, Git 배포 버전으로 대체하지 않는다.
- 활동 학생: 최근 7일 `last_seen_at`(정상 인증된 요청). Google 로그인/현재 온라인 상태가 아니다. 3일/7일 이상 미접속 집계는 접속 시각이 있는 학생만 포함한다. 접속 시각 없음, 도입 후 관측 없음, 보관 기간 내 관측 없음은 별도로 설명한다. 기존 관측 시작일과 30일 오류 보관 정책을 재사용한다.
- 최근 오류 학생: 최근 30일 서버에 기록된 오류가 있는 학생 수. 입력/권한/사용량/서버 오류를 구분한다. 서버에 도달하지 않은 네트워크 실패를 추정하지 않는다.
- 타임라인: 학생 제출/재제출 revision, 휴지통 제외 사진 생성, 완료 편집 버전 업로드, lock 시작/종료 감사, 제출 결과 오류만 사용한다. 각 기록의 원래 시각과 출처를 유지하며 관리자 첨삭·초안 저장·일반 접속을 제출로 만들지 않는다. 최근 30일 중 최대 12건이다.

## 구조 및 성능
초기 진입은 기존과 같이 session 후 요약 API 1회다. 원고·사진 원본·전체 이벤트는 브라우저에 내려보내지 않는다. 활동 요약/미제출 계산은 기존 학생 활동 화면과 공통 SQL을 사용한다.

| 항목 | 이전 | 변경 후 |
|---|---:|---:|
| 초기 대시보드 API | 1 | 1 |
| 대시보드 D1 조회 | 캠페인 없으면 2, 있으면 3 | 항상 9 |
| 100학생/20사진 기존 fixture 응답 | 303 B | 약 3.8 KB |
| 1,001기사/104학생/40사진 fixture | 비교 가능한 기존 통합 기능 없음 | 약 6.4 KB |
| 활동 학생 상세 전송 | 없음 | 최근 5 + 확인 필요 5 이내 |
| 타임라인 전송 | 없음 | 12건 이내 |

기능 확장으로 집계 수와 payload는 증가하지만 학생/기사 수에 비례한 요청이나 N+1은 없다. 집계는 병렬 실행하며 영역별 실패를 독립 표시한다. 실제 workerd D1에서 compound SELECT 제한을 확인했으므로 타임라인은 3종씩 두 개의 제한된 조회 후 서버에서 정렬·12건 제한한다. 단순 Node SQLite 테스트만으로 호환성을 판단하지 않는다. 신규 index는 추가하지 않는다.

## 연결 및 회귀
카드는 실제 anchor와 기존 createNavigation을 사용한다. 기사 상태 필터, 과제 캠페인/유형/미제출 필터, 학생별 사진/유형, 활동 학생/3·7일/오류/미제출 조건, 편집 프로젝트를 hash로 전달한다. 직접 진입·reload·back/forward를 검증한다. 과제 생성은 기존 폼과 roster lazy loading을 재사용한다.

스켈레톤은 정적이며 불필요한 animation을 추가하지 않는다. 빈 값은 0, 집계 실패는 `—`/영역 오류로 구분한다. 시간은 KST, 초과 마감 및 실제 오류만 경고색이다. 데스크톱 6열 KPI/비대칭 2열, 좁은 화면 3·2열 KPI/단일 콘텐츠 열을 사용한다. 카드 focus와 일반 링크의 새 탭 동작을 유지한다.

권한·CSRF·OAuth·회원 연결·기사/사진 제출·lock/업로드 API는 변경하지 않는다. 대시보드 GET은 기존 관리자 확인 및 no-store 응답을 사용한다. 운영 merge 시 Worker를 먼저 반영하고 동일 commit의 프런트엔드가 뒤따라야 한다. 이번 작업에서는 PR까지만 생성한다.
