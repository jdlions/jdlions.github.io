# 학생 활동 현황

## 의미와 한계

- 최근 접속: 기존 세션·활성 회원 검증을 통과한 학생의 API 요청. Google 로그인 성공이나 현재 온라인 상태가 아니다. Google 로그인 날짜는 기존 members.last_login_at을 그대로 사용하며 로그인 흐름을 수정하지 않는다.
- 과제 확인: 학생 페이지에 배정 과제 목록을 실제 표시한 뒤, 보이는 탭에서만 보내는 빈 POST 보고. 서버는 인증·Origin/CSRF와 본인 배정 존재를 확인한다. 정독을 증명하거나 클라이언트 보고를 신뢰할 수 있는 감사 증거로 간주하지 않는다. 숨겨진 탭, 빈 목록, 단순 사전 로딩은 보고하지 않는다.
- 기사/사진 제출: 기존 서버 처리의 시도와 결과를 각각 기록한다. 성공, 입력·제출 조건 오류(4xx), 권한·대상 오류(401/403/404), 사용량 제한(429), 서버 오류(5xx)를 구분한다. 원래 업무 응답은 변경하지 않는다. 미완료·기록 실패는 성공/실패로 단정하지 않고 결과 미확인으로 표시한다.
- 서버에 도달하지 않은 네트워크 단절·클라이언트 오류는 수집하지 않는다. 별도 클라이언트 오류 수집 API나 heartbeat는 추가하지 않았다.
- 기록 없는 학생은 필터에서 무조건 장기 미접속자로 분류하지 않는다. 과거 Google 로그인 기록조차 없음 / 스키마 적용 기준일 이후 요청 관측 없음 / 보관기간 내 관측 없음 / 활동은 있으나 접속 시각 미확인을 구별한다. 기준일은 migration 적용 시각이며 실제 코드 배포 전 공백도 관측 불가 구간이다.

## 저장·성능·보안

0013_student_activity.sql은 기준일 1행, 학생별 최근 요약, 제출 이벤트 테이블만 추가한다. 회원 ID·고정된 활동/오류 분류·서버 시각·임의 시도 ID만 저장한다. 원고, 사진, 파일명, URL, OAuth token, 비밀번호, 이메일, IP, User-Agent, 원문 오류 메시지와 요청 본문을 저장하지 않는다.

접속과 과제 확인은 각 학생별 5분 간격으로 제한한다. bounded 메모리 gate로 반복 요청의 추가 DB 작업을 생략하고, 새 isolate에서도 기존 D1 시각을 먼저 읽으며 조건부 UPSERT로 저장 간격을 지킨다. cache는 영구·분산 메모리가 아니므로 cold isolate에서는 읽기/조건부 갱신 비용이 추가될 수 있다. 제출은 매 실제 요청마다 시도·결과를 별도로 기록하고 늦은 이전 제출 응답이 최신 시도 결과를 덮어쓰지 못하게 한다.

기록은 waitUntil로 업무 처리와 분리한다. 장애 시 원문 없이 activity_record_failed 코드만 로그에 남기며 기존 로그인·조회·제출을 막지 않는다. DB 장애나 Worker 강제 종료 시 기록 손실 가능성을 숨기지 않는다. 현재 제출 상태는 활동 로그 추측이 아닌 기존 과제·기사 테이블의 진행 중(active) 배정 슬롯 집계다. 최초 로그인 전 member_assignment_targets도 기존 방식 그대로 합산한다.

GET /api/admin/student-activity는 기존 서버 admin 권한만 허용한다. 이름과 필요한 활동 요약만 반환하며 본문/내부 메모/다른 개인정보를 반환하지 않는다. POST /api/activity/assignment-view는 학생 본인 활동만 갱신하고 client 제공 학생 ID/시각을 받지 않는다. 기존 인증/세션/Origin/CSRF/CORS/no-store는 유지한다.

기존 회원 삭제 보호는 그대로다. 새 관측 테이블의 알려진 member_id만 비업무 참조로 인식하고 ON DELETE CASCADE로 정리한다. 새로운 알 수 없는 소유권 컬럼은 계속 fail-closed한다.

## 보관과 적용

상세 제출 이벤트·오류 표시는 30일, 최근 요약은 90일 보관한다. 기존 Worker scheduled handler가 매일 UTC 18:15(03:15 KST)에 새 활동 데이터만 정리한다. 기존 members.last_login_at 및 업무 기록의 보관정책은 변경하지 않는다. 예약 실행 실패는 Cloudflare의 scheduled invocation 결과로 확인한다. 정리가 지연돼도 UI의 오류 필터/표시는 30일 범위만 사용한다.

이 PR은 운영에 적용하지 않는다. 0013은 기존 migration을 수정하지 않으며 자동 승인 목록에 추가하지 않았다. 운영 적용 전 안전 점검·별도 승인 하에 0013을 먼저 적용하고 Worker(예약 실행 포함) → 같은 commit의 Vercel 순서로 배포한다. 스키마가 아직 없어도 기존 학생 업무 기록 작업은 실패를 격리하므로 유지되지만 새 관리자 현황은 사용할 수 없다.

검증은 가상 데이터만 사용한 로컬 빌드 Preview와 실제 workerd/D1 격리 runtime에서 수행한다. 운영 D1, 운영 Worker/Vercel, Google Drive 파일을 수정하지 않는다. 기존 외부 Vercel Preview의 실계정 로그인 검증과 구분한다.
